## S7 — Ougi framework + 3 Ougis (2026-07-23)

- `shared/ougi.ts` holds the framework: `OugiDefinition { id, name, description, durationTicks, onFire/onTick?/onEnd? }`, an `OUGIS` registry, and a `CHARACTERS` table (`characterId → ougiId`). Definitions are pure sim functions so they're unit-testable and the client can read their names/descriptions, but only the authoritative room ever *fires* them — the client's prediction sim never does, which keeps the "server-side effect" property the plan asked for. Framework rule, enforced by comment and test: a duration Ougi may only buff through generic `NinjaState` fields (`dashRangeMultiplier`), never private state, so a KO can clear every buff without knowing which Ougi was running.

- Three Ougis, one per character (identical base stats otherwise): **Ember/Shockwave** (instant radial burst, damage falling off linearly to nothing at 220px, knockback, shatters cover in the blast), **Gale/Surge** (5s: dash reach and the TP tank both ×2, TP topped up between dashes), **Shade/Cross Slash** (four instant cardinal beams, each stopping at the first wall or obstacle it cleaves, shattering anyone caught in a lane).
