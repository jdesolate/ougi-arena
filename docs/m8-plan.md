# Ougi Arena — M8: Visual/UX Overhaul (post-MVP milestone)

## Context

The MVP shipped (S1–S17, live at ougi-arena.j-desolate53.workers.dev). This milestone is a full visual and functional overhaul across the three screens (homepage, lobby, arena) toward a modern-retro Japanese console aesthetic, plus weapon attack animations, hit feedback, an arcade HUD, a match-start countdown that finally teaches the controls, and pause/quit game-loop controls.

**Decisions made with the user:**
1. **No true isometric projection.** Keep the top-down grid; deepen the existing faux-depth (taller pillars with cast shadows, wall faces, tile texturing, stronger `ySortDepth` occlusion). The sim and input math stay untouched.
2. **One sim change is in scope:** fan (tessen) knockback — push the hit target 1 tile. Longsword's "cleaves light cover in one hit" is already effectively true (20 dmg vs hay's 16 HP); kunai already matches its spec. Opus session per model policy.
3. **In-game art = code-drawn runtime textures + CC0 packs** (Kenney etc., credited in `docs/asset-credits.md`). Still no AI-generated sprite sheets or arena tiles — AI can't hold a consistent palette or grid across 16x16 frames, tiles must seam-match, and the ninja sprite is runtime-recolored per character. **Brand/marketing art may be AI-generated** (revised 2026-07-27), **and so may large fixed-size in-game art with no grid or tiling constraint** (revised again below) — character portraits, weapon/skill icons at one fixed size, match-end banners, arena backdrop art, UI frame ornaments. The rule is the constraint, not the location: one image at one size is fair game; anything that must tile, align to a grid, or stay consistent across frames is not.
4. **Controls are taught during a real countdown, not in a manual (2026-07-27).** Playtesting found the weapon unreachable: attacking is not its own input, it's a release with under `TAP_DRAG_THRESHOLD` (10px) of drag on the same press-and-hold that charges TP, so a player who never taps their own ninja only ever dashes. The fix goes where attention already is — a server-gated pre-match countdown with a control legend under it. Rejected alternatives: a cosmetic countdown (the sim starts on the same tick `phase` flips, and `runBotAI()` decides on the first callback, so bots would dash at a player reading "3"), and a landing-page "How to play" panel (one more thing between a stranger and Quick Play, and forgotten by the time it matters).
5. **The overloaded press-and-hold gesture is documented, not fixed, this milestone (2026-07-27).** Abandoning a charge throws a swing, because both live on the same press. Ship the legend first and re-judge once players actually know the gesture; a dedicated attack key or a hold-threshold rework is a feel change that doesn't belong in a visual milestone.
6. **The design system realigns to the logo (2026-07-27).** S18 built an ink-wash/lacquer/gold vocabulary; the logo that landed after it is bold cartoon-arcade — heavy black outlines, ember-orange vs ice-blue split, a rough-edged italic wordmark, no gold anywhere. The logo wins. S19.5 rewrites the tokens before S20 bakes the old palette into generated textures; S20–S22 below are re-expressed in the new vocabulary.

**Current-state facts the sessions rely on:**
- All UI is DOM overlays in one `index.html` `<style>` block — no CSS tokens. Screens: `#lobby` (form + room views), `#hud` top bar, `#match-end`.
- Arena renders via per-frame `Graphics` in `GameScene.drawWorld()`; ninjas are single tinted 16x16 Kenney sprites (`skins.ts`); pillars are runtime-generated textures with 34px top-face rise and Y-sort occlusion; particles in `scenes/effects.ts`. `world-palette.ts` is the single color table shared with `ui/map-thumb.ts` and `ui/portrait.ts`.
- Weapons have **no real animations** — `GameScene.weaponEffect()` is a particle burst per cell + squash tween. No knockback on any weapon today (knockback machinery exists in Shockwave's `dashBudget` push and `collision.ts` `KNOCKBACK_BONUS`).
- **No pause/Esc/quit exists.** Lobby→game is one-way (`lobbyEl.hidden = true`, Phaser game never destroyed, URL pinned at `/r/<code>`). Match-end offers only host rematch. HP is shown only as the over-sprite bar, never in the HUD.

## Sequencing rationale

- **Tokens first (S18)** — every later UI session consumes the design vocabulary instead of inventing colors.
- **Brand realignment (S19.5) before S20** — S20 generates pillar/wall/floor textures from `world-palette.ts`, and S22 styles a HUD from the DOM tokens. Changing the palette after either is done means redoing both; changing it now is one file of CSS plus the palette table (verified: all 29 token references live in `style.css` alone).
- **Arena depth (S20) before the HUD rebuild (S22)** — taller pillars change canvas composition/margins the bottom HUD must fit around.
- **Countdown + controls (S22.5) after the HUD rebuild** — it's the third full-screen overlay alongside `#match-end`, which S22 restyles; doing it after means one overlay vocabulary instead of styling it twice.
- **Fan knockback (S23, Opus) paired immediately with its visualization (S24, Sonnet)** — same S14/S15 pattern: a sim change is never left unplayable across a context reset.
- **Pause/quit (S25) last among structural changes** — riskiest session (first-ever teardown path); nothing else depends on it, so a failure can't block cosmetic sessions.
- **S26 polish/ship-check** absorbs cross-screen inconsistencies, like S17 did for M7.

## Risks

- **S25 teardown**: client assumes a game is never destroyed. Hazards: `allowReconnection` holding a ghost seat on a deliberate quit (needs consented leave), dangling Phaser RAF/listeners after `game.destroy()`, stale module-level state into the next join. Budget spillover to a second session; commit the pause overlay separately from the teardown.
- **S22.5 countdown vs the client's own clock**: the server freezing is only half of it — `GameScene` runs a local prediction sim on its own accumulator and would happily dash a ninja the server is refusing to move, producing a snap-back the instant the freeze lifts. Both sides must gate on the same phase, and rematch (which already resets prediction state on `"finished" -> "playing"`) now goes through `"countdown"` first, so that transition needs re-checking rather than assuming it still fires.
- **S23 knockback vs reconciliation**: a server push of the local player at rest is a new case for S9's snap-back gating — must be verified explicitly.
- **HP-in-HUD is new plumbing**, not just styling (flagged in S22).
- **Verification constraint**: the Browser pane historically can't composite frames (S6–S17); live checks use the established `window.__scene` hook (always reverted before commit) + DOM inspection; sim behavior relies on the vitest suite (106 tests today).
- **S19.5 is a palette change, not a repaint of everything**: the risk is a half-migration leaving ember and gold both reading as "the accent". Gold must end the session with one defined job (KO/victory) or be gone; no token may keep a lacquer-era name.
- **S25.5 swaps replace working code-drawn art** — a swap that loses per-character recoloring or per-map palette switching is a regression, not a polish. Keep the code path until the image is judged better in place.
- **Scope-cut levers, in order**: AI art swaps (S25.5, optional by construction) → wobble-shatter (S24) → floor tile texturing (S20) → Settings entry in the pause modal (ship Resume/Quit only). Neither S19.5 nor S22.5 is a cut lever — cutting S19.5 re-opens the brand mismatch that motivated it, and cutting S22.5 leaves the weapon undiscoverable, which is a functional defect rather than missing polish. If S22.5 must shrink, drop the countdown's polish (hold the legend), never the legend.
